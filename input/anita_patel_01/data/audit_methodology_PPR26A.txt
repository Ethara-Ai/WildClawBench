PPR-26A Competitive Portal Audit - Methodology
Author: Anita Patel
Last updated: 2026-10-08

Evidence triangulation requirement:
Each audit finding must be supported by at least two independent evidence sources drawn from:
  - Input artifacts (design briefs, competitor annotation photos, whiteboard captures, usability recordings)
  - Figma API data (comments, component metadata, frame modification history)
  - Notion API data (audit database pages, structured findings, severity ratings)

Output specification:
File: output.json
Each finding object must contain:
  - evidence_sources: list of (artifact name, Figma comment ID, Notion page reference)
  - competitor_pattern: descriptive label of the competitor practice observed
  - severity: as recorded in Notion (authoritative source when conflicts exist)
  - audit_status: current status from Notion findings
  - linked_frame: Figma frame ID from the active working file

Sorting rule: primary sort by severity descending (high > medium > low), secondary sort by evidence source count descending.

Source authority hierarchy:
  1. Notion database entries (authoritative for severity and status)
  2. Figma comments and component data (authoritative for frame references)
  3. Input artifacts (corroborating evidence, never override API sources for structured fields)
  4. Whiteboard captures (lowest priority, Notion wins on any conflict)

Delivery: Save output.json to filesystem, then notify Lila the audit is ready for review.
