# Verified findings for script/check_route_contracts.py.
#
# Format:  <api>::<METHOD> <path>[::<FINDING>]
# Seed findings use the pseudo-route <api>::SEED <table>.<field>.
# Omitting ::<FINDING> silences every finding on that route; every entry below
# is scoped to a single finding on purpose, so a NEW defect class appearing on
# an allowlisted route still surfaces. The grammar is byte-compatible with
# script/lost_writes_allowlist.txt, and the read-shaped POSTs below are the
# same routes that file already vouches for -- the two checkers gate opposite
# halves of one contract and share a single notion of "a human read this".
#
# ONLY the ERROR tier gates. WARN findings are deliberately absent from this
# file: they are meant to be read, not silenced.

# =====================================================================
# VERIFIED BENIGN -- the contract is intentional, there is nothing to fix.
# =====================================================================

# Salesforce sObjects are an open schema BY DEFINITION: the field names are the
# customer's org metadata, not ours, so extra="allow" is the vendor contract and
# extra="forbid" would reject every custom field (Custom_Field__c). The handler
# funnels through _extract_fields(), which takes either {"fields": {...}} or
# top-level keys. This is the one place in the fleet where an open body is right.
salesforce-api::POST /services/data/v59.0/sobjects/{sobject}::OPEN_BODY_SCHEMA
salesforce-api::PATCH /services/data/v59.0/sobjects/{sobject}/{record_id}::OPEN_BODY_SCHEMA

# Read-shaped POSTs: the vendor models a READ as a POST because the query is too
# large or too private for a query string. Nothing the caller expects to survive
# the call is stored, so an ignored key cannot become a lost write -- it degrades
# to a wrong projection returned in the SAME response. That is strictly weaker
# than the class this ERROR tier exists to stop. Residual risk acknowledged: a
# silently-ignored filter returns unfiltered results, so tighten these to
# extra="forbid" if either search surface ever grows a filter an agent leans on.
algolia-api::POST /1/indexes/{index}/query::OPEN_BODY_SCHEMA
google-calendar-api::POST /calendar/v3/freeBusy::OPEN_BODY_SCHEMA
